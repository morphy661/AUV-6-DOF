实验日期：2026-08-21
数据集：`six_dof_hybrid_telemetry_0_300m_focus_v3`
模型：结构化融合 BiLSTM-attention
实验类型：控制变量的重新训练式特征消融

## 一、实验控制条件

四个模型使用完全相同的数据集、任务级训练/验证/测试划分、归一化统计、模型结构、随机种子、损失函数、优化器、学习率、早停规则、时间连续性策略和正式维护工单策略。唯一变化是训练和推理时被屏蔽的输入特征。

模型仍然只根据验证集联合宏平均 F1 保存最佳检查点。测试集只在检查点冻结后运行，不参与模型选择。

实验组为：

1. `baseline`：保留全部特征；
2. `motion_loss_evidence`：屏蔽六个推进器的运动推力损失证据及其时间差分；
3. `simplified_response_residual`：屏蔽九个简化动力学响应特征及其时间差分；
4. `motion_plus_response`：同时屏蔽上述两组特征。

基线重训在第 17 个 epoch 得到验证联合宏平均 F1 `0.805543`，与原 V3 检查点完全一致，证明本次重训流程成功复现原模型。

## 四、判断

### 1. `motion_loss_evidence` 可以从神经网络输入中移除

重新训练后，验证集原始误报率从 8.70% 降至 5.91%，测试集从 12.61% 降至 10.24%；验证联合 F1 基本不变（0.8055 变为 0.8054），测试联合 F1 略有提升。测试集推力损失窗口召回率小幅下降 3.54 个百分点，但正式推力损失工单召回率保持 77.78%，完全失效工单召回率保持 100%，并继续保持零虚假工单。

这说明六个 `motion_loss_evidence` 对神经网络而言不是必要输入，并且可能造成了对简化运动残差信号的重复使用和过度自信。它仍可保留在正式工单证据层中，不必从整个诊断系统删除。

### 2. 简化动力学响应不能直接删除

删除后虽然误报下降，但验证联合 F1 从 0.8055 降至 0.7702，验证推力损失工单召回率从 66.67% 降至 33.33%，测试推力损失工单召回率也从 77.78% 降至 55.56%。其他传感器特征不能完全补偿这部分信息。

因此，简化动力学响应是有价值但不够稳健的故障信号。后续应重构或条件化该残差，而不是将其删除。

### 3. 两组同时删除不可接受

同时删除两组特征不仅没有稳定获得更低误报，还在验证集和测试集各产生了 1 个虚假正式维护工单，推力损失工单召回率也下降。因此该方案不应继续使用。

## 五、V3.1 的直接修改建议

V3.1 的第一项有效修改应是：

- 神经网络输入屏蔽六个 `motion_loss_evidence` 及其时间差分；
- 保留简化动力学响应特征；
- 保留 `motion_loss_evidence` 在正式维护工单证据层中的使用；
- 暂时不修改 BiLSTM-attention 架构、时间连续性参数和 FTC 规则。

这项修改能够在不损害正式故障处理能力的情况下，使测试原始误报相对下降约 18.8%，时间决策误报相对下降约 25.8%。但是测试原始误报率仍为 10.24%，所以它只是 V3.1 的第一项修复，不是误报问题的最终解决方案。

下一项修复应针对简化动力学响应的域稳定性：使用相同动力学参数、任务轨迹和扰动条件构建正常/故障配对任务，减少模型把随机动力学差异解释为推力损失的可能性。完成配对训练后，再判断是否需要把简化残差升级为包含阻尼、恢复力和扰动基线的条件化残差。

## 六、实验产物说明

当前消融检查点属于实验模型。它们依赖预处理阶段的输入屏蔽，不能直接替换演示程序中的 V3 检查点。正式 V3.1 需要把输入掩码写入检查点元数据和统一推理接口后重新验收。

本实验目前只使用一个固定训练种子。它足以完成受控定位，但在正式采用输入掩码前，还应使用少量额外训练种子确认误报下降方向不是随机初始化造成的偶然结果。
